# 项目交接上下文

> 最近更新：2026-11-24

## 当前状态

项目处于概念设计与玩法原型验证阶段。Godot 4.7.2 Standard 已安装；`prototype/` 包含第三人称移动、对话/商人/牌战 NPC、背包交易、三套可切换主题卡组与图鉴、双向即时传送，以及体力费用制回合战斗。

仓库当前主要用于沉淀《拿拍》的产品方向和设计决策。

## 已确认事项

- 项目中文名：《拿拍》。
- 游戏采用 3D 表现。
- 项目不是乒乓球游戏。
- 拍子对应现实球拍。
- 不同球拍对应不同武器类别，需要具有实质玩法差异。
- 默认采用近距离第三人称角色跟随视角，体验参考《GTA 5》和《原神》。
- 世界充满未来感，基于当代科技趋势进行富有想象力的向前推演。
- 建模顺序为世界观优先：先构建不依赖《拿拍》IP 的完整未来文明，再选择切入角度融入。

- 已用 headless 脚本 `tests/balance_formation.gd` 对实时布阵做首轮平衡基线（三阵营 × 五关 × 六种补位/体力模式，每格 6 局）：玩家即时补位时 15/15 格全胜；补位节奏压到 5 秒后 BOSS 掉到 0–33%，放宽到 3 秒又回到 17–100%，说明胜负几乎由「补位节奏」单变量决定；三阵营仅时长不同（BOSS 31/40/64 秒），教学与普通关在全部模式下 100% 且 7–12 秒结束。候选调参（敌方补位提速、前段加压等）见 `docs/BALANCE_BASELINE_V0_1.md`，尚未确认。
- 按「提高卡费 / 放慢补位 / 减少开局单位」方向做过第二轮阶梯实验（`tests/balance_tuning.gd`，原型已加 `opening_stamina`、`card_cost_multiplier`、`battle_cost_multiplier`、`battle_reinforce_cooldown` 四个默认不生效的调参开关）：全局卡费 ×1.25 时总体 74%、×1.5 时 46% 但重炮几乎全 0%，先打崩高费阵营；补位冷却 2 秒与 3 秒无差别（体力回复才是瓶颈）；战斗中补位加价 ×1.5 + 布阵体力按阵营 75/85/95 时总体 91%，BOSS 仍只有 17–33%。结论是三条杠杆不能同时同幅生效，建议拆为「补位加价 + 差异化布阵体力 + 关卡分级加压」，待确认。
- 2026-11-24 按“敌方同时只在场 1 个单位”重做五关：每关一个量身定制的单体敌人（训练木桩 260/6@2.6、烈焰自爆兵 320/8@1.6 亡语 20、穿甲狙击手 520/12@2.2 穿透、裁判机兵 1400/13@2.1、冰霜术士 460/8@1.8 压制），击破后不补位，敌方空场 3 秒判我方胜。引擎新增 `enemy_limit`（补位上限）与 `enemy_reinforce`（是否补位）两个关卡字段，`_try_enemy_reinforce` 双重拦截；新增单位阶段系统（卡定义 `phases` 阈值数组 + `formation_unit.phases/phase_index` + `_apply_unit_phases()`），首个 BOSS `boss_referee` 用 65% / 30% 两个阈值进入“破防穿透 → 压制恢复”两阶段。支线压制改为卡面属性 `suppress_regen`，不再按 `level_id + card_id` 绑定。
- 单体版平衡结果（`tests/balance_formation.gd` 重跑）：教学 13–20s、普通 15–28s、精英 21–42s、BOSS 54–70s、支线 22–72s；三阵营代理胜率除“完全不补位打 BOSS（0%）”与“重炮支线（50%）”外全部 100%，BOSS 己方阵亡 12–19。BOSS 专项标定 1400/13、1400/11、1100/12 三档在 5 秒补位下均 24/24 全胜，其中 1400/13 的时长与阵亡最贴合目标，选为当前档位。结论详见 `docs/BALANCE_BASELINE_V0_1.md` 第 8 节。
- 2026-11-24 按“只提高卡费”做单变量实验（`balance_tuning.gd` 六档 1.0/1.1/1.25/1.4/1.5/1.75，其余全默认，单体关卡、每格 8 局）：总胜率 100% → 96%，平均时长 28.3 → 41.1 秒，即卡费只拉长节奏、几乎不提难度；疾锋突击团 1.0–1.75 五关时长完全一致（5 费 ×1.75 仍在 2 体力/秒的支付能力内），重炮 BOSS 从 1.4 倍起掉胜率（88% → 63% → 50%），灵羽 BOSS 1.5 倍已到 94.8 秒撞突然死亡。安全上限 1.25，1.4 是临界。同时给原型加了 `ui_enabled` 开关：headless 平衡脚本跳过 UI 重建，修掉长时间模拟在 `_refresh_hand` 里 signal 11 崩溃的问题。
- 2026-11-24 **关卡表收敛为只打磨第一关**：`level_definitions` 与 `LEVEL_ORDER` 只剩教学关 `CH0-01`，其余四关（`CH1-01` / `CH1-E01` / `CH0-B01` / `CH1-S01`）及 `solo_dummy / solo_bomber / solo_sniper / solo_frost` 已删除；`LEVEL_SHORT_NAMES` 只留「第一关」，默认 `level_id = "CH0-01"`。第一关为**纯小怪、无 BOSS**：4 只灵羽单位 `aero_004` 嘲讽盾卫 (1,0) / `aero_001` 长弓游侠 (0,0) / `aero_002` 穿风猎手 (2,0) / `aero_003` 冰霜术士 (1,1)，`enemy_hp_multiplier = 1.3`、`enemy_reinforce = false`。`boss_referee` 与 `_apply_unit_phases()` 保留为「预留 BOSS·未启用」。
- 第一关生命倍率标定（`tests/level1_probe.gd`，3 秒补位、每档每阵营 8 局）：1.3 → 14.8/15.6/18.8 秒全胜；1.5 → 17.1/18.1/21.0 全胜；1.6 → 18.3/18.4/22.7 全胜；1.8 → 20.0/21.6/25.9 全胜；2.0 → 94.6/90.7/94.9 秒、38%/75%/63%；3.0+ 全 0%。即 1.3–1.8 只拉长时长不改胜负，2.0 断崖式翻盘。取 1.3 定位为「稳定能过、只教机制」的教学关。
- 2026-11-24 补牌机制调整（待试玩）：布阵阶段仍是「出牌立即补 1 张」，**战斗中改为每 `hand_refill_interval`（默认 2.0 秒）补 1 张**，手牌面板显示「下一张 x.x s / 补牌已满」；同时新增**换牌**——选中手牌后点体力面板的「换牌 N」按钮，花 2 体力丢牌换 1 张，每场 3 次，布阵与战斗都可用。探针 `tests/refill_probe.gd` 显示 `hand_refill_interval` 取 0/1.0/1.5/2.0/3.0 在第一关代理模拟里毫无差别（全 100%、13.8–19.8 秒、手牌空窗恒为 0），说明短关卡里补牌速率不是瓶颈，瓶颈是体力（5 费 ≈ 2.5 秒一张）。结论见 `docs/BALANCE_BASELINE_V0_1.md` 第 11 节：补牌只能当手感旋钮，不能当难度旋钮。
- 玩家状态面板采用左上角紧凑屏幕 HUD，探索时仅显示生命和经验；体力仅在牌战面板显示。生命初始 30 且战斗间保留，胜利获得 25 经验、每 100 经验升一级并发 1 天赋点。

## 协作约定

1. 后续对话中，只有用户明确认可或确定的方向才能进入 `DECISION_LOG.md`。
2. 助手提出但用户尚未确认的内容，只能作为候选方案记录。
3. 产品方向发生变化时，同时更新产品方向、决策记录和本交接文档。
4. 涉及实际功能调整时，需要提交并推送代码、更新相应产品文档并重启服务。
5. 开发环境不需要兼容旧系统或旧版本数据；合同或数据结构变化应显式迁移或重建开发数据，不在运行时代码中加入旧版兼容分支。
